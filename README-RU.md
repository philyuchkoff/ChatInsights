# ChatInsights
## Ваш личный граф знаний, о существовании которого вы не подозревали
![My Personal Vault](https://i.imgur.com/6J00Gu1.png)

ChatInsights — это Python-приложение для обработки **JSON-экспортов ChatGPT, Claude и Deepseek**, анализа концепций разговоров и создания структурированного хранилища (vault) Obsidian для управления знаниями. Также оно извлекает пары данных для потенциального дообучения (fine-tuning) LLM.

> ⚡️ Вдохновлено этим постом на Reddit: [Mining Your AI Conversation History — r/ChatGPTPro](https://www.reddit.com/r/ChatGPTPro/comments/1jzzgie/mining_your_ai_conversation_history_the_complete/)
>
> Изначально я создал этот инструмент для управления собственными беседами с GPT, но этот пост настолько точно совпал с моим видением, что я решил довести проект до конца и поделиться им.

## 🆕 Что нового

### Версия 3 (текущая) — декабрь 2025

| Версия | Поддерживаемые платформы | Ключевые особенности |
|---------|--------------------------|----------------------|
| v1 | Только ChatGPT | Базовый экспорт разговоров, отслеживание концепций, обучающие данные |
| v2 | ChatGPT + Claude | Поддержка нескольких платформ, автоопределение, очистка пустых файлов |
| **v3** | **ChatGPT + Claude + Deepseek** | **Заголовки моделей, блоки рассуждений (thinking), сводки, цепочки рассуждений** |

#### 🚀 Поддержка платформы Deepseek
- Полная поддержка экспорта разговоров Deepseek
- Обработка уникальной структуры сообщений Deepseek `fragments` (REQUEST, RESPONSE, THINK)
- Автоопределение отличает Deepseek от формата ChatGPT
- Добавлена радиокнопка Deepseek в выбор платформы

#### 🏷️ Заголовки с идентификацией модели
Во все экспортируемые файлы `.md` и `.txt` теперь добавляется заголовок:
```
# Model: gpt-4o / deepseek-chat / Claude
# Title: Conversation Title
# Date: YYYY-MM-DD HH:MM:SS

============================================================
```

**Поддержка платформ:**
- ✅ **ChatGPT**: извлекает `model_slug` из метаданных сообщений (например, `gpt-4o`, `gpt-5-instant`)
- ✅ **Deepseek**: извлекает поле `model` из сообщений (например, `deepseek-chat`, `deepseek-coder`)
- ⚠️ **Claude**: по умолчанию указывается «Claude» (Anthropic не включает версию модели в экспорт)

#### 🧠 Извлечение блоков рассуждений Claude
- Извлекает внутренние блоки рассуждений/размышлений Claude из разговоров
- Блоки рассуждений помечаются суффиксом `(Thinking)` в выходных файлах
- Захватывает текст `thinking` из блоков `content[*].type='thinking'`
- Работает с расширенным режимом размышлений (extended thinking) Claude
- Также захватывает блоки `tool_use` с суффиксом `(Tool Use)`

#### 📝 Сводки разговоров Claude
- Извлекает созданные ИИ сводки разговоров из экспортов Claude
- Сводки отображаются в отдельном разделе в начале каждого файла разговора:
```markdown
## Conversation Summary
[Текст сводки]

============================================================
```

#### 🔗 Поддержка цепочек рассуждений Deepseek
- Извлекает фрагменты `THINK` как блоки рассуждений с суффиксом `(Thinking)`
- Фрагменты `REQUEST` сопоставляются с сообщениями пользователя
- Фрагменты `RESPONSE` сопоставляются с сообщениями ассистента
- Корректная обработка структуры Deepseek `mapping` с массивами `fragments`

### Основные изменения версии 2

- **Поддержка Claude**: обработка экспортов разговоров Anthropic Claude
- **Автоопределение**: автоматическое определение платформы по структуре JSON
- **Выбор платформы**: ручной выбор платформы (auto/chatgpt/claude)
- **Очистка пустых файлов**: автоматическое перемещение пустых (0 КБ) «untitled» файлов в отдельную папку
- **Улучшенная сортировка файлов**: исправлена функция сортировки для извлечения дат из имён файлов

### 🛠️ Улучшения для разработчиков и качества (август 2026)

- **Рефакторинг кода**: монолит разбит на пакет `chatinsights/` (парсеры, GUI, CLI, трекер, обучение, i18n) с тонкой точкой входа.
- **Юнит- и интеграционные тесты**: 110+ тестов, покрывающих парсеры, потоковую обработку, CLI, i18n и обучающие данные (`pytest`).
- **Потоковая обработка больших файлов**: экспорты свыше 50 МБ обрабатываются потоково через `ijson`, а не загружаются целиком в память.
- **CLI-режим**: обработка без графического интерфейса через `chat-insights-cli` (или флаг `--cli`) — удобно для серверов и CI.
- **i18n интерфейса**: GUI полностью переведён на английский и русский (переключается в настройках).
- **YAML frontmatter**: файлы `.md` разговоров в Obsidian получают заголовок title/date/model для Dataview и Templater.
- **Поддержка симлинков**: `--symlink-conversations` создаёт символьные ссылки вместо копирования разговоров в хранилище Obsidian — экономия диска.
- **Резервное копирование конфигурации**: `config.json` копируется в `config.json.bak` перед каждым сохранением.
- **Валидация**: понятные сообщения об ошибках при некорректном JSON, обработка BOM, пустых и повреждённых файлов.
- **CI pipeline**: GitHub Actions запускает ruff, black, mypy и тесты на Python 3.10–3.13.

## Возможности

*   **Обработка экспортов нескольких платформ:** читает `conversations.json` из **ChatGPT, Claude и Deepseek** и извлекает данные разговоров с автоопределением платформы.
*   **Идентификация модели:** в выходные файлы добавляются заголовки с указанием использованной модели ИИ (например, `gpt-4o`, `deepseek-chat`, `Claude`).
*   **Извлечение блоков рассуждений:** захватывает расширенные размышления Claude и цепочки рассуждений Deepseek с суффиксом `(Thinking)`.
*   **Генерация текстовых журналов:** создаёт отдельные файлы `.txt` для каждого разговора, организованные по месяцам и годам в подкаталоге `data`.
*   **Создание хранилища Obsidian:** автоматически генерирует структуру хранилища, готовую для Obsidian:
    *   **Заметки о концепциях:** создаёт файлы `.md` для ключевых концепций, обнаруженных в заголовках разговоров (с настраиваемым регулярным выражением). Включает метаданные, тренды эволюции, связанные концепции и ссылки на соответствующие разговоры.
    *   **Журналы разговоров:** копирует исходные журналы разговоров в подкаталог `Obsidian/Conversations` (с сохранением месячной структуры) и конвертирует их в файлы `.md` с YAML frontmatter (title/date/model), что позволяет напрямую связывать их из заметок о концепциях и использовать с Dataview/Templater.
    *   **Карты контента (MOC):** генерирует `Concepts-MOC.md` со ссылками на все обнаруженные заметки о концепциях.
    *   **Дашборд:** создаёт `Concept-Dashboard.md` с запросами Dataview для визуализации данных о концепциях в Obsidian.
    *   **Анализ терминов:** генерирует `Recurring-Terms.md`, выделяющий часто используемые термины в заголовках, которые могут быть потенциальными новыми концепциями.
*   **Извлечение обучающих данных:** генерирует пары «инструкция-ответ» из взаимодействий пользователь-ассистент в формате JSONL или CSV, подходящих для дообучения LLM.
*   **Оптимизированный рабочий процесс:** процесс переноса журналов разговоров в хранилище Obsidian полностью автоматизирован внутри приложения.
*   **GUI:** удобный графический интерфейс на базе Tkinter (английский и русский).
*   **CLI-режим:** обработка без GUI для скриптов, серверов и CI — см. [Командная строка](#командная-строка).

## Требования

*   Python 3.10 или новее
*   Tkinter (обычно входит в стандартную установку Python)
*   Опционально: `ijson` (для потоковой обработки больших экспортов свыше 50 МБ)

# Текстовая версия:
(Обычно я просто дважды кликаю по файлу)

1.  **Запустите скрипт:**
    ```bash
    python chat-insights-app.py
    ```
2.  **Выберите файл экспорта:** во вкладке «Import & Process» нажмите «Browse», чтобы выбрать ваш файл `conversations.json`, скачанный из ChatGPT, Claude или Deepseek.
3.  **Выберите платформу (необязательно):** приложение автоматически определяет платформу, но при необходимости вы можете вручную выбрать ChatGPT, Claude или Deepseek.
4.  **Настройте (необязательно):**
    *   Измените «Output Directory», если не хотите использовать каталог по умолчанию (`~/ChatInsights`).
    *   Измените «Your Name», «Assistant Name» и «System Name» в соответствии с вашими предпочтениями. Эти имена используются при генерации текстовых журналов и обучающих данных.
    *   Перейдите во вкладку «Concept Tracker» и настройте список «Core Concepts to Track». Каждая строка должна быть в формате `ConceptName: regex_pattern`.
5.  **Обработка и анализ:** нажмите кнопку **«Process & Analyze Concepts»**. Будут выполнены следующие шаги:
    *   Обработка JSON-экспорта.
    *   Создание журналов `.txt` в подкаталоге `data`.
    *   Генерация `pruned.json` и `training_data.jsonl` в подкаталоге `data`.
    *   Анализ заголовков разговоров на основе заданных концепций.
    *   Генерация структуры хранилища Obsidian (файлы `.md` для концепций, MOC, дашборд, термины) в подкаталоге `Obsidian/Concepts`.
    *   **Автоматическое копирование** журналов разговоров `.txt` из `data` в `Obsidian/Conversations` с переименованием в `.md`.
6.  **Откройте в Obsidian:**
    *   После завершения обработки нажмите кнопку «Open Output Folder», чтобы увидеть все сгенерированные файлы.
    *   Нажмите кнопку «Open Obsidian Vault». Она откроет папку `Obsidian/Concepts`.
    *   В Obsidian выберите «Открыть папку как хранилище» и укажите каталог `Obsidian/Concepts`, созданный инструментом (например, `~/ChatInsights/Obsidian/Concepts`).
    *   Теперь вы можете просматривать заметки о концепциях, MOC, дашборд и переходить по ссылкам внутри заметок (например, `[[conversation_filename]]`), чтобы напрямую открывать соответствующий журнал разговора.

### 💻 Командная строка

Обработка без графического интерфейса:

```bash
chat-insights-cli conversations.json [опции]

# Полный конвейер с собственными именами:
chat-insights-cli conversations.json --user-name "Я" --assistant-name "GPT"

# Пропустить обучающие данные или отслеживание концепций:
chat-insights-cli conversations.json --no-training
chat-insights-cli conversations.json --no-concepts

# Экономия диска: симлинки вместо копирования разговоров в Obsidian:
chat-insights-cli conversations.json --symlink-conversations

# Принудительно выбрать платформу или указать каталог вывода:
chat-insights-cli conversations.json --platform chatgpt --output ~/MyVault
```

Точка входа GUI тоже поддерживает CLI-флаг: `python chat-insights-app.py --cli <файл> [опции]`.

### 📚 Универсальный шаблон отслеживания концепций

Этот инструмент позволяет отслеживать повторяющиеся темы и топики в вашей истории разговоров с ChatGPT. Вы можете задать интересующие вас концепции, и приложение автоматически будет помечать их и организовывать в вашем хранилище Obsidian.

#### 🛠 Как это работает
Каждая концепция сопоставляется по простым ключевым словам. Вам не нужно знать регулярные выражения — просто перечислите связанные термины через `|` (вертикальная черта), и инструмент будет сопоставлять любой из них.

#### 📌 Стартовый шаблон (отредактируйте его!)

Вставьте это во вкладку **Concept Tracker**, чтобы начать:

```
AI: AI | Artificial Intelligence | GPT | Claude | LLM | Deepseek 
Machine Learning: Machine Learning | ML | Training | Fine-Tuning  
Coding: Python | Script | Code | Programming  
Frameworks: Framework | Architecture | Structure | System  
Optimization: Optimization | Optimizer | Performance | Speed  
Server Tools: Server | RCON | Admin | Discord Bot  
Mental Health: Mental Health | Depression | Anxiety | Support  
Neurodiversity: Neurodivergent | ADHD | Autism  
YourProjectName: [ Добавьте свои ключевые слова сюда ]  
```

#### 🧠 Советы
- Вы можете добавить больше концепций по тому же принципу:  
  `ConceptName: keyword1 | keyword2 | keyword3`
- Ключевые слова **не чувствительны к регистру**, так что не переживайте о заглавных буквах.
- Для личных терминов (например, кодовых имён или псевдонимов) просто добавьте строку вида:  
  `ATLAS: ATLAS | A_T_L_A_S`  
- Будьте настолько широкими или конкретными, насколько хотите — это ваша карта знаний.

## Структура выходных данных

Предполагается каталог вывода по умолчанию (`~/ChatInsights`):

```
~/ChatInsights/
├── config.json             # Хранит настройки приложения
├── config.json.bak         # Автоматический бэкап предыдущих настроек
├── data/                   # Исходные результаты обработки
│   ├── April_2025/         # Пример папки месяц/год
│   │   ├── convo_title_1_dd_mm_yyyy_hh_mm_ss.txt
│   │   └── ...
│   ├── May_2025/
│   │   └── ...
│   ├── _empty_untitled_cleanup/  # Сюда перемещаются пустые untitled-файлы
│   │   └── cleanup_log_*.txt
│   ├── conversation_titles.txt # Список, используемый трекером концепций
│   ├── pruned.json             # Структурированные данные разговоров (с информацией о модели)
│   └── training_data.jsonl     # Выходной файл обучающих данных по умолчанию
├── Obsidian/
│   └── Concepts/             # Корень вашего хранилища Obsidian
│       ├── Conversations/      # Скопированные и переименованные журналы разговоров
│       │   ├── April_2025/
│       │   │   ├── convo_title_1_dd_mm_yyyy_hh_mm_ss.md
│       │   │   └── ...
│       │   └── May_2025/
│       │       └── ...
│       ├── AI.md               # Пример заметки о концепции
│       ├── ATLAS.md            # Пример заметки о концепции
│       ├── ...                 # Другие заметки о концепциях
│       ├── Concepts-MOC.md     # Карта контента (Map of Content) для концепций
│       ├── Concept-Dashboard.md # Дашборд с запросами Dataview
│       └── Recurring-Terms.md  # Анализ часто встречающихся терминов
└── training_data.csv       # Необязательный вывод обучающих данных в формате CSV
```

## Известные ограничения

### Экспорты Claude
- **Нет версии модели**: Anthropic не включает информацию о том, какая модель Claude (Opus, Sonnet, Haiku и т. д.) использовалась в экспорте. Приложение по умолчанию показывает «Claude» в качестве имени модели.
- **Доступность блоков рассуждений**: блоки рассуждений появляются только в том случае, если во время разговора был включён расширенный режим размышлений (extended thinking).

### Экспорты ChatGPT
- Слаг модели зависит от того, включает ли OpenAI его в экспорт (в целом надёжно)

### Экспорты Deepseek
- Поле модели зависит от того, включает ли Deepseek его в экспорт (в целом надёжно)
- Требуется массив `fragments` в структуре сообщений

### Общие
- Очень большие экспорты (500 МБ+) обрабатываются в потоковом режиме; для максимальной производительности рекомендуется `ijson`
- В потоковом режиме использование памяти ограничено (а не растёт пропорционально размеру экспорта)
